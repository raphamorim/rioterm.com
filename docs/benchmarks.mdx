How fast a terminal feels comes down to a few separate things: how quickly it drains output from the PTY, how many frames it can paint, how long a keypress takes to reach the screen, and how much memory it holds while doing so. No single number covers all of them, so this page tracks each one with the suites other terminals already use. That way the results can be checked against published numbers from Alacritty, kitty, Ghostty and others.

## Methodology

All suites run on the same machine, on the same day, in a window of the same size, with each terminal on its default configuration and the same font. Each test runs five times and the median is reported.

| Suite | What it measures | Tool |
| --- | --- | --- |
| Plaintext I/O | Time to `cat` an 11 MB text file to the screen | [hyperfine](https://github.com/sharkdp/hyperfine) |
| vtebench | PTY read throughput across dense cells, scrolling regions and unicode | [alacritty/vtebench](https://github.com/alacritty/vtebench) |
| Parser throughput | ASCII, Unicode, CSI and image payloads, in MB/s | [kitty `kitten __benchmark__`](https://sw.kovidgoyal.net/kitty/performance/) |
| Termbench | ManyLine, LongLine, FGPerChar and FGBGPerChar workloads | [cmuratori/termbench](https://github.com/cmuratori/termbench) |
| Input latency | Keypress to glyph on screen, median and p99.9 | [Typometer](https://pavelfatin.com/typometer/), [Is It Snappy](https://isitsnappy.com/) |
| Frame rate | Full-screen 256-color repaint | [DOOM-fire-zig](https://github.com/const-void/DOOM-fire-zig) |
| Memory | Idle RSS of one window, six seconds after a cold launch | `ps` / [btop](https://github.com/aristocratos/btop) |

A few things to keep in mind when you read these:

- Throughput suites such as vtebench measure how fast a terminal reads from the PTY. They say nothing about latency or frame pacing, so read them next to the latency plot.
- On macOS, windows that are hidden or covered get throttled. Keep the terminal under test visible and frontmost, or frame-rate numbers collapse.
- Terminals that support [synchronized updates](https://gist.github.com/christianparpart/d8a62cc1ab659194337d73e399004036) do better on full-screen redraw workloads, which matches how real TUIs behave.

For the speed of Rio's terminal core as a library, without any rendering, see [Rio-VT](/docs/rio-vt).
